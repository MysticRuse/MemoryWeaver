Rewind · Build Plan & Agent Hand-off

From wireframes to shipped, in phases

A spec-driven roadmap for building the reimagined Rewind (formerly MemoryWeaver) with Claude Code / Antigravity as the implementer. You act as orchestrator: you own the specs, gates and reviews; the agent owns the keystrokes. Every phase is a vertical slice that ships on its own and maps to a wireframe (1a–1g, 2a–2c).

A

How each feature moves — the spec-driven loop

Run this loop per feature. It is the "factory," not the product — structure is what lets vibe-speed coding stay shippable.

1
Write the spec, not the codeAuthor specs/<phase>_<feature>.feature.md from the template: Markdown intent + YAML schema (nesting >3 → YAML per Day 5) + Gherkin scenarios + eval cases. This is the contract.
2
Hand it to the agent against the harnessPrompt: "Implement specs/P1_multimedia_ingress per specs/HARNESS.md." The agent reads the harness rules (sandbox, no secrets on frontend, tests-first) and builds.
3
Run the eval gateLLM-as-judge + pytest + trajectory inspection score the run against the spec's eval cases. Below threshold → the agent self-repairs and re-runs. No green gate, no merge.
4
Human-in-the-loop review (the "Vibe Diff")Agent produces a plain-English summary of what changed + trajectory. You approve or send corrections ("no, not like that") — corrections are captured as new eval cases.
5
Update the tracker & version the specMove the ticket in specs/BUILD_TRACKER.md, tag the spec version. Shipped code is disposable; the spec is the source of truth.
6
Promote authority tierFeature graduates Read-only → Draft → Action-allowed only after eval coverage (trigger · execution · regression · token budget) is met.

Definition of done — the eval gate every ticket clears

Seven dimensions (Day 4 eval framework)
✓ Intent satisfaction✓ Functional correctness✓ Visual / behavioral✓ Cost / latency budget✓ Code quality✓ Trajectory quality✓ Self-repair

Plus per-spec: security STRIDE items closed · Gherkin scenarios green · no PII in logs · authority tier justified. Track session convergence (did the user get what they wanted), not just per-turn pass rate.
